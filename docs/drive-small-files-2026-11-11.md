# ทดสอบลดคำขอ Google Drive สำหรับไฟล์เล็ก

ทดสอบวันที่ 11 พฤศจิกายน 2026 โดยใช้ Google Drive จริงกับคลังจำลองสองคลังที่แยกจากคลังจริง ใช้ชุดเดียวกัน 1,154 ไฟล์ รวม 786,116 bytes มีไฟล์เล็ก 1,152 ไฟล์ ไฟล์ 280 KiB หนึ่งไฟล์ ไฟล์ว่างหนึ่งไฟล์ และ Junction สามจุด ทั้งสองรุ่นใช้สูงสุด 16 งานพร้อมกัน

| รอบสำรอง | คำขอรุ่นเดิม | คำขอรุ่นใหม่ | เวลารุ่นเดิม | เวลารุ่นใหม่ |
| --- | ---: | ---: | ---: | ---: |
| ครั้งแรก | 5,798 | 3,494 | 249.99 วินาที | 193.44 วินาที |
| ไฟล์ไม่เปลี่ยน | 1,172 | 25 | 40.59 วินาที | 20.57 วินาที |

ครั้งแรกลดคำขอ 39.7% และลดเวลา 22.6% รอบไฟล์ไม่เปลี่ยนลดคำขอ 97.9% และลดเวลา 49.3% รุ่นใหม่ส่ง multipart 1,152 ครั้ง ส่วนไฟล์ขนาดใหญ่และ manifest ใช้ resumable ตามปกติ รอบไฟล์ไม่เปลี่ยนรุ่นใหม่อ่าน inventory 6 หน้าและส่งเฉพาะ manifest วัดเวลาผ่าน Core ที่เผยแพร่หนึ่งรอบต่อเงื่อนไข รวมคำขอที่จัดการคลังและเก็บ snapshot รุ่นใหม่สำรองขณะรุ่นเดิมกำลังกู้คืนข้อมูลจำลองแบบอ่านอย่างเดียว เวลานี้ใช้กับชุดจำลองเท่านั้น

ทดสอบกู้คืนรุ่นใหม่ทั้ง snapshot ใหม่และ snapshot รุ่นเดิม ตรวจทุก byte ตรงกัน 1,154/1,154 ไฟล์ต่อชุด ไม่มีไฟล์เพิ่มจาก Junction และ snapshot แรกยังอยู่หลังสำรองซ้ำ การกู้คืนด้วยรุ่นเดิมดาวน์โหลดครบแล้ว ตัวตรวจหมดเวลาระหว่างเทียบไฟล์บนดิสก์ จึงตรวจต่อด้วย SHA-256 โดยไม่อ่าน Drive ซ้ำ ผลตรงกันครบ 1,154 ไฟล์

ทดสอบอัตโนมัติ 257 ข้อผ่านและ build Desktop, Worker, Tray ผ่าน วัด peak working set ของโปรแกรมทดสอบรุ่นใหม่ระหว่างสำรองและกู้คืนชุดจำลองที่ 157,417,472 bytes การทดสอบกู้คืน snapshot รุ่นเดิมด้วยรุ่นใหม่วัดได้ 69,607,424 bytes

Core ที่ใช้ทดสอบ Drive มี SHA-256 `415AB5646291FE0A2B88BF26E1355EB3D70FFB3C32BBEC0AA8D3CFA1D48D3656` แพ็กเกจติดตั้งเพิ่มเฉพาะข้อความแปลข้อผิดพลาดภาษาอังกฤษใน Core มี SHA-256 `C274A08B88C564B51DD162790E98906D3AE17768E0139C85156DB9482590A8F5` เปรียบเทียบ method definitions และ IL ตรงกันครบ 917 รายการ

รายงาน JSON อยู่ใน `%TEMP%/PCAutobackup-small-chunk-ab-b77fed69b5c4436dadc9ddbe797b73c4` ชื่อ `baseline-result.json`, `candidate-result.json` และ `compat-result.json`
