## ทดสอบหน้าต่างจริงจากโปรแกรมที่ติดตั้ง

ใช้ configuration แยกใน ignored artifacts/persistent-source-ui กับโฟลเดอร์และไฟล์จำลองสองรายการ ปิด schedule ของ fixture และไม่มี credentials ไม่สำรอง/กู้คืน/ล้างข้อมูลจริง

1. นำ A ออกแล้วกด **เลิกทำ**: A/B กลับมาลำดับเดิม
2. นำ A ออกแล้วกด **ยืนยันการนำออก**: เหลือ B ใน active sources และ pending history เป็นศูนย์ ตรวจจาก configuration ที่บันทึกแล้ว
3. นำ B ออกโดยไม่ยืนยัน: แถบ Undo/ยืนยันปรากฏ พร้อมจำนวนประวัติหนึ่งรายการ
4. รอจริงจนเกิน 60 วินาที: แถบซ่อน แต่ข้อความประวัติหนึ่งรายการและปุ่มคืนโฟลเดอร์/ล้างประวัติยังอยู่ ไม่ได้ปรับ timestamp หรือนาฬิกาเพื่อเร่งการทดสอบ
5. ปิดหน้าต่างด้วย Alt+F4 แล้วเปิด installed executable ใหม่ด้วย fixture configuration เดิม: ประวัติหนึ่งรายการยังอยู่และแถบที่หมดเวลาไม่กลับมา ตรวจไฟล์หลังปิดที่ประมาณ 84 วินาทีพบ pending หนึ่งรายการ
6. กด **คืนโฟลเดอร์**: B กลับมาเป็น active source ประวัติหมด A ที่ยืนยันนำออกแล้วไม่กลับมาด้วย
7. นำ B ออกอีกครั้ง กด **ล้างประวัติ**: มี dialog ถามยืนยัน โดย No เป็นค่าเริ่มต้น กด No แล้วประวัติหนึ่งรายการยังอยู่
8. กดล้างประวัติอีกครั้งแล้ว Yes: ประวัติและแถบหาย active sources ยังว่าง ตรวจ configuration สุดท้ายพบ active/pending เป็นศูนย์ทั้งคู่

SHA-256 และขนาดไฟล์จำลองเดิมตรง **2/2** แม้นำออก ยืนยัน และล้างประวัติแล้ว แสดงว่าคำสั่งเหล่านี้จัดการรายการสำรองและประวัติเท่านั้น ไม่ลบต้นฉบับ ปิดหน้าต่าง/Tray ของ fixture หลังทดสอบ แล้วเริ่ม Tray ของ configuration จริงเพียงหนึ่ง process

## การตั้งค่าจริงและขอบเขตตรวจ

SHA-256 configuration จริงและ startup Run key ก่อน–หลังตรงเดิม ตารางยัง enabled ทุกวัน 21:00 รอบถัดไปขณะตรวจคือ 9 พฤศจิกายน 2026 เวลา 21:00 +07:00 XML ของ Task Scheduler เปลี่ยนเฉพาะ StartBoundary ของ daily trigger จาก 8 เป็น 9 พฤศจิกายน เนื่องจาก installer refresh ตารางในวันใหม่ DaysInterval ยังคง 1 และเวลา 21:00 คงเดิม จึงไม่อ้างว่า XML ตรงกันทุก byte
